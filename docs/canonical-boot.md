# Raw-clone startup

From a fresh copy of the repository, with current Docker Desktop/Linux containers:

```powershell
docker compose up
```

No host Node/Python, generated host settings, or prior setup script is required.
Compose builds missing application images and starts the tools. The first build
needs internet; offline execution still requires previously cached matching images.
After source changes, use `docker compose up --build` to refresh application images.

Open http://localhost:8080 after gateway/website readiness. Demo accounts remain
`nong@example.com`, `sparkle@example.com`, and `admin@edemand.test`, password
`eDemand-2026!`. Dashboard and traces remain on ports 3000 and 16686.

## Initialization and ownership

1. A short-lived `bootstrap` container runs as the image's unprivileged `service`
   user, without networking, Linux capabilities or a source-directory mount.
2. On first boot it generates independent random local secrets in `stack-config`.
   On later boots it reuses them. Existing `.env.notifications` overrides are optional
   and read by Compose; no generated secret is exported to the host repository.
3. Each service receives only its own read-only volume subdirectory. For example,
   the API gets its database URL, but not the Keycloak admin or broker credentials.
4. Keycloak starts, then an idempotent configuration container adds scopes and the
   provisioner. The website starts only after this completes successfully.

Launch scripts are generated with Linux line endings in the configuration volume.
This avoids relying on shell-script line endings in Windows source checkouts.
Use a Docker/Compose version supporting volume `subpath` and optional `env_file`.

## Existing deployments

Keep the existing `.env.notifications` when adopting this startup mode. Bootstrap
adopts its values, preserving access to existing PostgreSQL/RabbitMQ/Keycloak data.
If an override changes a secret after initialization, startup refuses to rotate it
silently. Restore the matching settings before restarting. The configuration volume
must be included with database volumes in any backup/restore plan.

The old `compose.notifications.yml` is retained as the legacy operator template and
for CI adoption tests. Normal startup and PowerShell verification scripts now use
the canonical root file and scoped environments directly.

`start-notifications.ps1` remains an optional build-and-verify convenience command.
It no longer generates host secrets. `-PrepareOnly` validates source configuration.

## Fresh-volume rehearsal and reset

The local Windows rehearsal copies clean sources, runs the canonical Compose command
without a host env file, verifies the real flows, removes only its own fresh test
volumes, and restores the original stack:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\check-clean-start.ps1
```

This briefly stops the local website. Passing evidence records
`host_settings_required=false` and `boot_command=docker compose up`.

For an **intentional full reset of the current project**, this command deletes its
databases and generated secrets, returning the next boot to demo seed state:

```powershell
docker compose down --volumes --remove-orphans
```

Do not use that full reset to upgrade a deployment whose data you want to keep.

## Automated proof

The `canonical-boot` CI job uses a disposable project named `noti-ci-raw`. It tests:

- no `.env.notifications` before or after initial startup;
- non-root initialization, real browser login/registration and event delivery;
- restart without losing the newly registered domain accounts;
- adopting a separate legacy fixture's existing passwords/database volumes.

The CI-only shell script refuses to run outside a GitHub runner. It does not operate
on the user's Docker host. Check the workflow result for the exact commit being used;
local source tests are not proof of a successful deployed boot.

The JSON syntax used by `docker-compose.yml` is valid Compose/YAML. Its scoped
initialization model is generated by `scripts/canonical_compose.py` from an operator
service model, with credentials removed. Never commit a resolved config containing
local environment values.
